1. Pendahuluan

1.1 Tujuan Website

SIMKOS (Sistem Informasi Manajemen Kost) adalah aplikasi web untuk mengelola data kamar kost dan penghuni secara digital. Website ini memudahkan pengelola kost dalam:

  • Mencatat dan memantau ketersediaan kamar (kosong/terisi)
  • Mengelola data penghuni yang tinggal di kost
  • Melihat statistik okupansi dan data terbaru secara real-time
  • Mengelola akses dengan sistem login petugas dan admin

1.2 Fitur Utama

Dashboard

  • Kartu statistik: total kamar, kamar terisi, kamar kosong, total penghuni
  • Tabel penghuni terbaru (5 data terakhir)
  • Quick action buttons untuk tambah kamar/penghuni

Manajemen Kamar

  • Daftar kamar dengan pagination (5 per halaman)
  • Pencarian kamar berdasarkan nomor atau tipe
  • Tambah kamar baru (nomor, tipe, harga)
  • Edit data kamar (termasuk status KOSONG/TERISI)
  • Hapus kamar (hanya admin)

Manajemen Penghuni

  • Daftar penghuni dengan pagination (5 per halaman)
  • Pencarian penghuni berdasarkan nama atau nomor HP
  • Tambah penghuni dengan dropdown dinamis (pilih tipe → kamar kosong muncul)
  • Edit penghuni (otomatis update status kamar lama jadi KOSONG, kamar baru jadi TERISI)
  • Hapus penghuni (hanya admin)

Autentikasi & Otorisasi

  • Register petugas baru (role default: petugas)
  • Login dengan username/password (support "Ingat saya" 30 hari via cookie)
  • Role-based access: petugas bisa tambah/edit, admin bisa tambah/edit/hapus
  • Logout dengan session destroy

3. Desain Visual

3.1 Konsep Desain

SIMKOS menggunakan desain modern minimalis dengan prinsip:

  • Clean & Spacious: Banyak whitespace, padding generous, tidak penuh sesak
  • Hierarchy Jelas: Typography dengan size bertingkat (judul besar → subjudul → teks biasa)
  • Konsistensi Komponen: Semua card, button, tabel pakai border-radius 10-12px
  • Visual Feedback: Hover effects (translateY, box-shadow), status badges berwarna

3.2 Alasan Pemilihan Warna Biru (#3b82f6)

Warna biru dipilih sebagai primary color karena:

  1. Trust & Professionalism: Biru identik dengan kepercayaan, cocok untuk sistem manajemen data
  2. Readability: Biru cerah (#3b82f6) kontras tinggi dengan background putih, mudah dibaca
  3. Universal Appeal: Tidak terlalu feminine/masculine, cocok untuk semua audiens
  4. Trend Modern: Mengikuti design system populer (Tailwind CSS, Material Design menggunakan blue sebagai default)

3.3 Font Plus Jakarta Sans

Alasan pemilihan:

  1. Modern Geometric Sans-Serif: Desain bersih, profesional, tidak kaku
  2. Legibility Tinggi: Mudah dibaca di layar bahkan di ukuran kecil (0.75rem)
  3. Variable Weight: Mendukung 400/500/600/700 untuk hierarchy yang jelas
  4. Google Fonts: Gratis, fast CDN, tidak perlu hosting sendiri

8. Alur Halaman (User Flow)

8.1 Flow Register Petugas

[Buka /auth/register.php]
→ Isi form (nama, username, password min 6 char)
→ Submit → [proses_register.php]
  → Validasi (nama/username/password non-empty, password >= 6)
  → Check duplicate username
  → INSERT INTO users (password_hash via password_hash(), role='petugas')
  → Flash: "Registrasi berhasil, silakan login." (success)
  → Redirect ke login.php

8.2 Flow Login

[Buka /auth/login.php]
→ Isi username, password
→ Centang "Ingat saya (30 hari)" (opsional)
→ Submit → [proses_login.php]
  → SELECT * FROM users WHERE username
  → password_verify() cek password
  → Jika benar:
    → session_regenerate_id(true)
    → Set $_SESSION[user_id, nama, role]
    → Jika "remember" checked: issue remember token
    → Redirect ke index.php
  → Jika salah: Flash error → Redirect ke login.php

8.3 Flow Tambah Kamar

[Klik "+ Kamar Baru"]
→ requires auth (redirect jika tidak login)
→ [kamar/tambah.php]
  → Form: nomor_kamar, tipe, harga
  → Submit → [proses_tambah.php]
    → Validasi: semua field non-empty
    → INSERT INTO kamar (status auto-default 'KOSONG')
    → Flash: "Kamar berhasil ditambahkan!" (success)
    → Redirect ke list.php

8.4 Flow Tambah Penghuni (dengan Dropdown Dinamis)

[Klik "+ Penghuni Baru"]
→ [penghuni/tambah.php]
  → Load dropdown tipe: SELECT DISTINCT tipe FROM kamar
  → User pilih tipe → JavaScript fetch:
    → fetch('get_kamar.php?tipe=Standard')
    → Return JSON kamar kosong
    → Populate dropdown kamar_id
  → Submit → [proses_tambah.php]
    → BEGIN TRANSACTION
      → INSERT penghuni
      → UPDATE kamar SET status='TERISI'
    → COMMIT
    → Flash: "Penghuni berhasil ditambahkan!" (success)
    → Redirect ke list.php

8.5 Flow Hapus Data (Admin Only)

[Petugas klik "Hapus"]
→ [kamar/hapus.php atau penghuni/hapus.php]
  → require_admin('list.php')
    → Cek is_admin() (return $_SESSION['role'] === 'admin')
    → Jika BUKAN admin:
      → Flash: "Akses ditolak: hanya admin yang boleh menghapus data." (danger)
      → Redirect ke list.php
  → DELETE FROM kamar/penghuni WHERE id = :id
  → Flash: "Data ... berhasil dihapus." (success)
  → Redirect ke list.php

8.6 Flow Logout

[Klik "Logout"]
→ [auth/logout.php]
  → remember_forget() (clear cookie + DB token)
  → session_destroy()
  → Redirect ke auth/login.php

9. Teknologi

9.1 Stack Lengkap

Layer Teknologi Versi/Info
Front-End HTML5 Semantic tags (section, header, footer, nav, aside, main)
CSS3 Custom CSS, CSS Variables, Flexbox, Grid
JavaScript (Vanilla) ES6+, Fetch API, DOM Manipulation, LocalStorage
Font Awesome + Google Fonts v6.4.0 (CDN), Plus Jakarta Sans (400/500/600/700)
Back-End PHP 7.4+ (password_hash, SessionHandlerInterface)
PDO PostgreSQL driver (pgsql extension)
Database PostgreSQL 12+ (SERIAL, ILIKE, DATE, TIMESTAMP)
Auth PHP Native password_hash (PASSWORD_DEFAULT = bcrypt)
Remember Me Token Selector:Validator pattern (SHA256 hash)

9.2 Alasan Pemilihan Teknologi

PHP (Native)

Alasan:

  • Deployment mudah: hampir semua shared hosting support PHP tanpa config
  • Learning curve rendah: ideal untuk pemula web development
  • Built-in fungsi keamanan: password_hash(), htmlspecialchars(), prepared statements PDO
  • Tidak butuh build step (beda dengan Node.js yang butuh npm/bundler)

PostgreSQL

Alasan:

  • ACID Compliance: Transaksi penghuni + update kamar butuh atomicity
  • Advanced Features: Support ILIKE (case-insensitive search), SERIAL (auto-increment), constraint FK
  • Supabase Integration: Design-ready untuk deploy ke Supabase (config/database.php support DATABASE_URL)
  • Performance: Indexing lebih baik dari MySQL untuk query kompleks (JOIN)

Vanilla CSS (No Framework)

Alasan:

  • Full Control: Tidak ada class bawaan framework yang "magic"
  • Lightweight: File CSS hanya 1026 baris, tidak ada dead code
  • Educational: Pakai framework tanpa paham CSS dasar = bad practice
  • Custom Design: Design SIMKOS unik, tidak perlu class utility

Vanilla JavaScript (No jQuery/Framework)

Alasan:

  • Modern Browser Support: Fetch API, querySelector sudah support di semua browser 2020+
  • Performance: Vanilla JS lebih cepat dari jQuery (no library overhead)
  • Bundle Size: 0 KB dependency (jQuery = 30KB minified)
  • Learning: jQuery sudah deprecated di industri, Vanilla JS skill lebih transferable

10. Kesimpulan

10.1 Kelebihan Proyek

1. Design Modern & Profesional

  • UI minimalis dengan spacing konsisten
  • Hover effects smooth (translateY, box-shadow transitions)
  • Color palette semantic (hijau = kosong, kuning = terisi)
  • Responsive layout (sidebar collapsible, mobile-friendly)

2. User Experience Baik

  • Dashboard informatif (statistik + data terbaru langsung terlihat)
  • Dropdown dinamis (pilih tipe → kamar kosong muncul otomatis)
  • Pagination + search (tidak berat untuk data banyak)
  • Flash message jelas (sukses hijau, error merah)
  • "Ingat saya" 30 hari (user tidak perlu login terus-menerus)

3. Keamanan Terjaga

  • Password hashing (bcrypt via password_hash)
  • Prepared statements (semua query pakai parameter binding, no SQL injection)
  • Role-based access (admin bisa hapus, petugas tidak)
  • Remember token pakai selector:validator pattern (secure, detect token theft)
  • Session data di database (tidak bisa dicuri via file system)

4. Data Consistency

  • Transaction untuk penghuni + kamar (atomicity)
  • Sinkronisasi status kamar otomatis
  • Foreign key constraint (prevent orphan data)

5. Maintainability

  • CSS fully documented (1026 baris dengan komentar)
  • Separation of concerns (config, includes, auth, kamar, penghuni terpisah)
  • Reusable includes (header, footer, session, auth, role)
  • CSS Variables (ubah warna cukup edit `:root`)

10.2 Keterbatasan Proyek

Security

  • No CSRF Protection: Form tidak pakai token CSRF
  • No Rate Limiting: Login brute-force attack tidak ada protection

Features

  • No Soft Delete: Hapus data langsung DELETE permanent
  • No Audit Log: Tidak ada riwayat "siapa edit data apa kapan"
  • No Export Data: Tidak bisa export tabel ke Excel/PDF

Performance

  • No Caching: Query statistics jalan tiap page load
  • No Index: Kolom search belum ada database index

Code Quality

  • Inline SQL: Query SQL di file view, seharusnya di Model/Repository
  • Repeated Code: Pagination logic copy-paste
  • Magic Number: Limit hardcoded, seharusnya config
  • No Unit Test: Tidak ada PHPUnit test

10.3 Rekomendasi Pengembangan

Priority 1 (Critical Security)

  1. Tambah CSRF token di semua form POST
  2. Tambah rate limiting login (max 5 attempt per 15 menit)

Priority 2 (Essential Features)

  1. Implementasi soft delete dengan deleted_at
  2. Tambah audit log untuk tracking perubahan data

Priority 3 (UX Improvement)

  1. Buat modal custom untuk konfirmasi hapus
  2. Tambah loading state di dropdown dinamis
  3. Sidebar auto-collapse di mobile

Priority 4 (Performance)

  1. Tambah Redis caching untuk dashboard statistics
  2. Buat database index untuk kolom search

Priority 5 (Architecture)

  1. Refactor ke MVC pattern (Model-View-Controller)
  2. Buat Repository pattern untuk database queries
  3. Implement environment-based config (.env file)
